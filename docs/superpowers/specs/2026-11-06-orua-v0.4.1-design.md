# Orua v0.4.1 设计规格：失败可见性与「假闭合」收口

> 本规格在 v0.4.0（2026-11-06-orua-v0.4.0-design.md）之上增量演进，v0.1.0/v2/v3/v4 全部功能与测试保持有效。
> v0.4.1 不是新功能版本，而是 **v0.4.0 终验后的缺陷收口版本**：把「验证通过但用户看不见」与「失败被静默吞掉」两类问题从根上修掉。

## 1. 背景与问题陈述

v0.4.0 发布版实机验收的观感结论是「无法聊天 / 插件没用 / 群聊无响应」，但自动化测试全绿。逐项复盘后确认，根因不是功能缺失，而是三类系统性缺陷：

1. **失败被静默吞掉**：单聊生成失败后，`refresh-after-chat` 的整表重载会把刚画出的错误气泡擦掉；群聊失败只 `broadcast` 不落库，重开房间一片空白；`max_tokens` 无上限校验（实机库里真存过 `1935228928`），模型名与全局默认双空也能保存，直到后端 400 才暴露。
2. **假闭合（false closure）**：测试断言只证明「代码被执行了」，不证明「用户看得见」。到期提醒在同一同步 tick 内连续调 `toast()`，浏览器不会在同步循环中间上色，只有最后一次调用的文案留在元素上，但每次调用都各自返回 `true`，于是前面几条被记账并 `POST /done` —— 正文静默丢失。群「进行中」徽标同理：徽标读 `App.state.groups[].status`，而状态变更只写 `App.state.groupStatus`，徽标只能靠碰巧的整表刷新出现。
3. **版本号三处各说各话**：exe 文件/产品版本、后端 `/health`、前端侧栏脚注彼此不一致，用户无法判断手上跑的是哪个产物。

## 2. 目标

1. **失败必须可见**：单聊错误不被重载擦掉；群聊失败原因落库，重开房间能看到为什么停了；Bot 编辑器在提交前拦下越界值与双空模型。
2. **假闭合清零**：提醒 toast 每 tick 至多一条真正可见，未见不标完成；群「进行中」徽标在状态变更时实时出现，后端重启后不滞留。
3. **版本单一真源**：exe 文件/产品版本、`/health`、前端脚注统一为 `0.4.1.0`，脚注 boot 时读 `/health` 覆盖，反映实际连上的后端产物。
4. **发布指引落地**：README 补「打包与更新指引」，明确 `publish.cmd` 会连 `data` 一起清掉、备份与回拷步骤、发布后核对产物的方法。
5. **可证伪闸门**：把两处「假闭合」现场的断言固化成可重跑的 stub 检查脚本，且断言必须能被旧代码证伪。

## 3. 数据模型变更

### 3.1 `group_messages.role` 放开 `system`

```sql
-- 旧 CHECK
role TEXT NOT NULL CHECK(role IN ('user','assistant'))
-- 新 CHECK
role TEXT NOT NULL CHECK(role IN ('user','assistant','system'))
```

- `role='system'` 的语义：**群聊失败留痕，只给人看**。`bot_id` 为 `NULL`。
- 留痕不占「最近 12 条」上下文窗口、不进记忆提取快照——它是 UI 提示，不是对话历史。
- 前端重建房间时把 `role='system'` 渲染成群内提示（`sysnote`），不伪装成用户或 Bot 发的消息。

### 3.2 迁移：一次性原地重建

SQLite 的 `CHECK` 约束**不能 `ALTER`**，只能重建表：

```
PRAGMA foreign_keys=OFF
BEGIN
  DROP INDEX IF EXISTS idx_group_messages_group
  ALTER TABLE group_messages RENAME TO group_messages_old
  <用新 DDL 建表>
  INSERT INTO group_messages(id,group_id,bot_id,role,content,created_at)
    SELECT id,group_id,bot_id,role,content,created_at FROM group_messages_old
  DROP TABLE group_messages_old
COMMIT
PRAGMA foreign_keys=ON
```

- **幂等**：先查 `sqlite_master` 里该表的 `sql`，已含 `'system'` 则跳过。
- **DDL 单一来源**：`kGroupMessagesDdl` 常量同时供「新库建表」与「旧库迁移重建」使用，防止约束在两处各写一遍、改一处漏一处。
- **显式列名搬迁**：旧库多列/少列时是明确报错而不是静默错位。

## 4. 前端行为契约

### 4.1 单聊失败可见（`App.state.chatFailure`）

- 失败时把错误记入 `App.state.chatFailure`（按会话归属），`loadMessages` 重载后按会话重画错误气泡。
- **清疤只发生在「开始新一次生成」**，不在 `onDone` 清。
  - 关键事实：后端失败时仍会发 `event: done`。在 `onDone` 清疤会把刚记下的失败立刻抹掉——这条由真实浏览器实测抓到，stub 假流已按该帧序构造。
- 切走再切回仍跟随该会话；下一次成功不留旧疤。

### 4.2 群聊失败留痕

- 失败原因与自动暂停原因以 `role=system`、`bot_id=NULL` 落库。
- 前端重建房间时渲染成群内提示；正常发言照常渲染。

### 4.3 Bot 编辑器提交前校验

| 字段 | 规则 | 越界行为 |
|---|---|---|
| `max_tokens` | 1–65536 的整数，留空 = 2048 | 拦在提交前，toast 说明允许范围与当前值 |
| 模型名 | Bot 自己填的模型 **或** 设置里的默认模型至少有一个非空 | 双空时拦下，提示「到设置 → API 填写模型，或在此指定」 |

- `input` 补 `max` 属性；模型占位文案不再误导。
- 合法值照常提交，且**提交用户填的数**（不得静默换成默认值）。

### 4.4 到期提醒 toast（每 tick 至多一条真可见）

- 主窗口 15s 轮询 `GET /api/v1/reminders?due=1`。
- **一个 tick 只允许一次 `toast()`**：取 `due_at` 升序最早的一条呈现。
- 其余待发条数以「（另有 N 条待提醒）」并进**同一条**文案，不另起第二次 `toast()`。
- **只有这条真落到 toast 元素上才记账并标完成**，未见不标完成，未提示的排队到下一轮。

### 4.5 群「进行中」徽标实时性（`syncGroupStatus`）

- 新增 `syncGroupStatus(gid, state)`：同时写面板态 `App.state.groupStatus`、列表项 `App.state.groups[].status`，并 `renderChatList()`。
- SSE `status` 事件与 `group-start` / `group-pause` / `group-resume` / `group-stop` 四条命令的成功路径统一改走它。
- **后端重连纠正**：`backendOnline` 在 `false→true` 转换时经 `resyncGroups()` 刷新群表并重渲染聊天列表，清除陈旧徽标。
  - 刷新与重渲染**必须串行**：并发时 `renderChatList` 会快照到陈旧数组把旧徽标又写回去（该失败模式由断言 J11c 抓到，先前一行版修法正是如此失败）。
- 已知范围限定：群只能从房间面板启动，离开房间后该群的 `status` 事件停止投递；若它期间在服务端自行停止，徽标会滞留到最后已知值，重新开房或后端重连即纠正。

## 5. 版本与发布

### 5.1 版本单一真源（三处同源 0.4.1.0）

| 位置 | 作用 |
|---|---|
| `AiCompanion.App.csproj` `<Version>0.4.1.0</Version>` | exe 文件版本 / 产品版本 |
| `backend` `/health` → `{"version":"0.4.1.0"}` | 运行时版本 |
| `index.html` `#foot-version` | 侧栏脚注，boot 时读 `/health` 覆盖 |

- 脚注 boot 时读 `/health` 覆盖，**避免 UI 与实际后端产物各说各话**。
- 另补 `<Product>Orua</Product>` 与 `<Description>`，使 exe 属性页可辨识。

### 5.2 打包与更新指引

- `publish.cmd` 会**连 `data` 一起清掉**——必须在发布前备份 `data/`，发布后回拷。
- 发布后核对产物的方法：看 `/health` 的 `version` 与侧栏脚注是否一致。

## 6. 错误处理

- 无新增错误码；沿用 1001–1004、404、400。
- 失败一律**可见**：单聊错误气泡常驻该会话，群聊失败落库留痕，编辑器越界拦在提交前。

## 7. 测试策略

### 7.1 后端单测

- `group_messages` 迁移幂等：旧库（无 `system`）→ 重建 → 数据零丢失；再次打开不重复重建。
- `role='system'` 可写入且不进入「最近 12 条」上下文与记忆快照。

### 7.2 可证伪的前端闸门（`scripts/checks/*.mjs`）

三个 stub 检查脚本，**断言必须能被旧代码证伪**——修复前副本跑应有 FAIL，修复后全 PASS：

| 脚本 | 断言数 | 覆盖 |
|---|---|---|
| `check-reminders-ui.mjs` | 109 | 提醒呈现/记账、群徽标实时性与重连纠正（J 组） |
| `check-bot-skills-ui.mjs` | 54 | 插件页技能提交链（按 Bot 分槽、失败回滚、成功复原可信态） |
| `check-failure-visibility.mjs` | 19 | 单聊错误不被重载擦掉、群聊留痕渲染、编辑器越界拦截 |

- 保留为可重跑闸门而不是随 SDD 工作区一起删掉：这两处「假闭合」是回归高发区。

### 7.3 集成

- `test_api.ps1` 全绿（v0.1.0–v0.4.0 全部既有断言）。
- `ctest` 全绿（v0.4.1 当时基线 82 用例 / 695 断言；v0.5.0 追加 `test_v5.cpp` 后为 91 / 777）。
- WPF 构建 0 警告 0 错误。

## 8. 明确排除项

- 群聊中的技能调用（v0.4.0 既定排除，v0.4.1 不动）。
- 系统级通知 / 托盘（提醒仍用前端 toast）。
- 未读消息的服务端计数推送（本地水位方案即可）。
- 技能自定义参数 UI（首版全部默认参数）。
- `sysinfo` 的 CPU 占用采样（v0.4.0 已知偏差，v0.4.1 不补，留待后续）。

## 9. 验收标准

1. 单聊生成失败后错误提示留在对话区（不被整表重载擦掉、切走再切回仍跟随该会话、下一次成功不留旧疤）。
2. 群聊失败原因落库，重开房间能看到为什么停了；留痕不伪装成用户/Bot 消息。
3. Bot 编辑器拦下越界 `max_tokens`（1–65536）与「模型名 + 设置默认模型双空」，提示可操作。
4. 到期提醒每 tick 至多一条 toast 真正可见；正文与待发计数合并进同一条；未见不标完成。
5. 群「进行中」徽标随运行状态实时出现/消失；后端重启后陈旧徽标被整表刷新清除；持续在线不重复刷新（无抖动）。
6. 版本三处统一 `0.4.1.0`；侧栏脚注读 `/health`。
7. README 含「打包与更新指引」，明确 `publish.cmd` 会清 `data`。
8. 三个 stub 闸门全 PASS（修复前副本应 FAIL）；`ctest` 82 用例 695 断言全绿；`test_api.ps1` PASSED；WPF 构建 0 警告 0 错误。
9. v0.1.0/v2/v3/v4 功能与自动化测试全绿；旧库升级零破坏。
