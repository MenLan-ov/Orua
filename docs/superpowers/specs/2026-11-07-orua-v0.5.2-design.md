# Orua v0.5.2 设计规格：数据持久化与插件体系

> 本规格在 v0.5.1（2026-11-07-orua-v0.5.1-design.md）之上增量演进，v0.1.0–v0.5.1 全部功能与测试保持有效。
> **版本号规则变更**：自本版起全部版本改用 `0.x.y` 语义，此前为 `1`–`5.1`。

## 1. 目标

修掉三个用户可见缺陷，并确立「用户数据与程序产物分离」这条长期约束：

1. **头像在更新后消失**——不只是头像，`app.db`、`config.json` 里的 API Key 都会一起没。
2. **插件页 UI 混乱**——文字被压断行、区块被裁到视口外。
3. **无法添加插件**——配置里明明有 `plugins` 数组，界面上却没有任何入口。

## 2. 根因

### 2.1 数据目录与产物目录耦合

`MainWindow.DataDir` 取 `AppContext.BaseDirectory + "data"`，即 `dist\Orua\data`。而 `publish.cmd` 的第一件事是：

```bat
if exist "dist\Orua" rmdir /s /q "dist\Orua"
```

`data\` 就在 `dist\Orua` 里面，于是每次发布都会删掉：

| 文件 | 丢失后果 |
|---|---|
| `app.db` + WAL/SHM | Bot、群、全部聊天记录、技能开关、提醒 |
| `config.json` | DPAPI 加密的 API Key、插件配置、主题 |
| `uploads\*.png` | **上传的 Bot 头像** |

README 里写的是「更新前必须备份数据」，把责任推给用户——这是设计缺陷，不是操作规范问题。**任何需要用户手工备份才能安全升级的更新机制都是错的。**

### 2.2 插件页布局缺陷（两个独立问题）

**问题 A：文字被压断行。** 原布局 `.memory-layout` 是 `grid-template-columns: 240px 1fr`，左栏固定 240px。「计算器」「定时提醒」这类中文标题在 240px 内被 padding 和间距吃掉后放不下，于是折成「计算\n器」。

**问题 B：Bot 技能名被挤成「计...」。** 全局样式有 `input, textarea, select { width: 100% }`。`.bot-skill-row` 是 `display:flex` 的 `label`，里面是 `<span>名称</span><input type="checkbox">`。checkbox 继承了 `width:100%`，实测撑到 **221px**，把 286px 的行宽占满，只剩 30px 给文字，于是 ellipsis 成「计...」。

**问题 C：自制插件区块被裁到视口外。** 6 张技能卡片是整块大卡片，把主区高度吃光，下面的区块滚出视口。

### 2.3 插件功能是「半成品」

`config.json` 有 `plugins` 数组，`cfg::load` / `cfg::save` 能读写，`EventBus::loadPlugins` 能加载，`scheduleWebhook` 能分发——**唯独没有任何 HTTP 接口或 UI 入口**。

用户想加自制插件只能：
1. 手工编辑 `%LOCALAPPDATA%` 或 `dist\Orua\data\config.json`
2. 重启后端（`loadPlugins` 只在 `main()` 启动时调一次）

这不是「bug」，是**功能只做了一半**：后端管道全通，入口完全缺失。

## 3. 设计

### 3.1 数据目录迁移（一次性、幂等、失败不阻塞）

```
旧：<安装目录>\data
新：%LOCALAPPDATA%\Orua
```

**为什么是 `%LOCALAPPDATA%`**：这是 Windows 上「按用户存放应用数据」的标准位置。不需要管理员权限，卸载/重装/换版本都不受影响，且天然按用户隔离（DPAPI 密文本来就绑定用户，语义一致）。

**迁移时机**：两处都做，互为兜底。
- `publish.cmd`：删产物**之前**，若发现旧 `dist\Orua\data` 就用 `robocopy /E /XC /XN /XO` 搬走。
- WPF 启动时：`MigrateLegacyDataIfNeeded`，目标目录已存在且非空则跳过。

**幂等性**：迁移只在目标不存在或为空时执行，重复启动、跨版本升级都不会覆盖新数据。

**WAL/SHM 处理**：`app.db-wal` / `app.db-shm` 是运行期文件，直接拷贝可能与主库不一致。迁移后删除新位置的这两个文件，让 SQLite 自行重建（主库 `app.db` 已包含 checkpoint 后的数据）。

**失败策略**：`publish.cmd` 中 robocopy 退出码 ≥8（真实失败）时**中止发布**，绝不继续删除产物。WPF 中迁移异常只记 Debug 日志并退回旧目录，不阻塞启动。

### 3.2 插件 CRUD API

```
GET    /api/v1/plugins            → { plugins: [...], available_events: [...] }
POST   /api/v1/plugins            → { plugin: {...}, updated: bool }
DELETE /api/v1/plugins/{name}     → { deleted: name }
```

**同名 POST 视为更新**：不额外开 PUT，因为「插件」的自然主键就是名称，前端「编辑」与「新增」共用一张表单，省掉一条分支。

**校验规则**（后端权威，前端只做提前提示）：

| 字段 | 规则 | 拒绝理由 |
|---|---|---|
| `name` | 非空、≤64 字符、去首尾空白 | 空名称无法作为主键 |
| `url` | 必须以 `http://` / `https://` 开头、≤2048 字符 | 拒绝 `file://`、`javascript:` 等误配 |
| `events` | 仅接受四个已知事件，去重 | 未知事件永不触发，用户会误以为插件在工作 |
| 总数 | ≤32 | 防止配置膨胀 |

**热重载**：每次写操作后调 `ev::EventBus::instance().loadPlugins(sc.plugins)`，无需重启后端。这是与旧行为的关键差异——旧版必须重启。

### 3.3 插件页布局

```
┌─────────────────────────────────┬──────────────┐
│ 插件                [+ 添加插件] │              │
├─────────────────────────────────┼──────────────┤
│ ┌─ 内置技能 ──────── 6 个 ────┐ │ ┌─ Bot 技能 ┐│
│ │ [计算器] [时间日期]          │ │ │ [糯米 ▼]  ││
│ │ [系统信息] [HTTP 请求]       │ │ │ □ 计算器  ││
│ │ [读取文件] [定时提醒]        │ │ │ □ 时间日期││
│ └──────────────────────────────┘ │ │ ...       ││
│ ┌─ 自制插件 ──────── 0 个 ────┐ │ └───────────┘│
│ │ 还没有自制插件…              │ │              │
│ └──────────────────────────────┘ │              │
└─────────────────────────────────┴──────────────┘
```

- 主区 `minmax(0,1fr)` 自适应，侧栏固定 **280px**（实测下限：再宽主区不足 400px，网格只能排一列）
- 技能卡片 `repeat(auto-fill, minmax(170px, 1fr))`，描述 `-webkit-line-clamp: 2` 限两行
- `.bot-skill-row input[type="checkbox"] { width: auto }` 显式收回复选框
- `.view-header` 补样式（此前完全没有 CSS，按钮会掉到标题下方）
- `#view-plugins` 加 padding（`.view` 本身无内边距，标题会贴窗口边缘）
- 两列各自 `overflow-y: auto`，`<980px` 时侧栏落到下方

### 3.4 头像健壮性

- `<img onerror>` 回退 emoji 占位，避免破图与 `ERR_BLOCKED_BY_ORB` 控制台噪音
- 头像 URL 附 `?v=<avatar_path>` 缓存破坏参数，换头像后立即生效（此前浏览器会缓存旧图）

### 3.5 版本号显示

前端 boot 时从 `/health` 读版本并覆盖脚注，原逻辑是 `.split('.').slice(0,2).join('.')`——为 `0.5.1.0` 设计的（显示 `v0.5.1`）。改成 `0.5.2` 后会被截成 `v0.5`，看起来像没升级。改为完整三段显示。

## 4. 验收标准

1. 数据目录为 `%LOCALAPPDATA%\Orua`；`dist\Orua` 内不含用户数据
2. 旧布局首次启动自动迁移；`publish.cmd` 覆盖安装后 `app.db` / `uploads` / `config.json` 完好
3. 上传头像 → 重启应用 → 头像仍显示；文件缺失时显示 emoji 而非破图
4. 插件页标题与按钮同行右对齐；技能卡片两列、标题单行；「自制插件」首屏可见
5. UI 可添加插件：填表 → 保存 → 列表出现 → 重启后仍在
6. 校验拒绝：空名称 / 非 http(s) URL / 未知事件 / 超 32 个，均给出中文提示
7. 同名 POST 走更新（`updated: true`），不产生重复条目
8. 插件增删后日志出现新 `plugins loaded: N`，无需重启
9. 删除后列表与 `config.json` 同步移除
10. 版本三处同源 `0.5.2`，脚注显示 `v0.5.2`
11. v0.1.0–v0.5.1 全部自动化测试保持全绿

## 5. 测试策略

| 层次 | 手段 | 覆盖 |
|---|---|---|
| 配置层单测 | `test_v052.cpp`（4 用例 / 16 断言） | 插件读写往返、空列表、文件缺失、不影响服务字段 |
| API 层 | curl 直打 | 增删改查、四类校验、持久化、热重载日志 |
| GUI 层 | `smoke_plugins.mjs` | 真实点击「添加插件」→ 填表 → 保存 → 校验拦截 → 删除，含布局断言 |
| 回归 | `smoke_gui.mjs` / ctest / 三闸门 | 聊天、后端、既有前端约束 |

**关键教训延续 v0.5.1**：凡「用户点击 → 前端请求 → 后端响应 → 界面渲染」的链路，验证必须从**用户动作**发起。本轮插件功能就是靠 `smoke_plugins.mjs` 真实点击才发现「保存后弹窗没关」「列表没刷新」这类只有端到端才暴露的问题。

## 6. 已知取舍

- **未做插件连通性测试**：保存时不验证 Webhook 是否可达。理由是加插件时对方服务可能尚未部署；失败只在日志里 `plugin webhook failed`。若后续需要，可加「测试连接」按钮。
- **插件鉴权未加**：Webhook 请求不带签名。本地单人应用场景下风险有限，但若未来支持多用户需补 HMAC。
- **侧栏 280px 是实测值**：更窄的窗口（<980px）会切到单列布局。
