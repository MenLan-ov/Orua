# v0.6.1 人设系统 — 设计

## 背景

v0.6.0 及之前，「这个 Bot 是谁」完全塞在 `bots.system_prompt` 一个字段里。用户想换一种说话风格，只能整体改写那段提示词；想让两个 Bot 共用同一套人物设定，只能手工复制，改一处忘一处。

参考稿（图 5）给出的形态是：人设是**独立的一页表单**——人设名、群内展示名、参与度、角色设定、管理员附加规则、系统提示词覆盖。这暗示人设应当是可复用的实体，而不是 Bot 的附属字段。

## 核心决策

### 1. 人设是独立实体，Bot 通过 `persona_id` 引用

新增 `personas_v2` 表，`bots` 加 `persona_id`（默认 `0` = 未绑定）。

为什么不内嵌进 `bots`：一条人设要能同时服务多个 Bot、同时覆盖私聊与群聊。内嵌就得复制多份，改一处漏一处。

`persona_id = 0` 时行为与 v0.6.0 **完全一致**——这是升级安全性的关键，旧库升级后不会静默改变说话风格。

### 2. 表名用 `personas_v2` 而不是 `personas`

`db.cpp` 里已经有一张遗留的 `personas` 表（`id/name/avatar/greeting/system_prompt/temperature/is_active/...`），它是 v0.5.x 一次性迁移进 `bots` 的数据源，迁移完成后就没人用了，但表还在。

新表结构完全不同。若沿用 `personas` 这个名字，`CREATE TABLE IF NOT EXISTS` 在旧库上会**静默跳过**（表已存在），随后所有查询都会因列不存在而失败。改名为 `personas_v2` 是成本最低的正确做法。

### 3. 拼接在 `db` 层，不在 `server.cpp`

`applyPersonaToPrompt(basePrompt, personaId)` 放在 `db.cpp`。

原因是群聊引擎（`group_engine.cpp`）不走 `resolveBotConfig`。最初把拼接写在 `server.cpp` 的 `resolveBotConfig` 里，结果私聊生效、群聊照旧用 `bot.system_prompt`——典型的「改一处漏一处」。放进 db 层后两边调同一个函数。

### 4. 拼接顺序：人设 → 附加规则 → Bot 提示词

```
角色设定
[附加规则]
<bot.system_prompt>
```

- 角色设定在最前：它定义「我是谁」，是最高权重的人格定义。
- Bot 提示词在最后：紧贴对话内容，模型对末尾指令更敏感，这样用户对这个人物的具体交代不会被冲淡。
- 附加规则居中：补充约束，但不该推翻角色本身。

`system_override` 非空时**整体替换**，此时角色设定与附加规则都不参与——避免出现「以为覆盖了、其实还混进了别的规则」这种极难排查的行为。

### 5. 人设与记忆叠加

最终上下文顺序：

```
system: 人设 + Bot 提示词
system: [长期记忆]
...历史...
user:   本轮输入
```

人设是「我是谁」，记忆是「我知道什么」，两者不互相替代。这个顺序由 `test_v061.cpp` 的单测钉住——顺序错了会让记忆细节冲淡人设，或让记忆被历史淹没。

### 6. 内置人设：幂等种子 + 不可删

首次建库种入三条（温暖陪伴 / 理性顾问 / 活跃群友）。只在 `personas_v2` 为空时插入——用户删掉某个内置人设后，下次启动不会又冒出来。

内置人设不可删：用户可能正依赖它的默认行为，删掉会静默改变对话风格。要改可以编辑（`updatePersona` 不限制 `builtin`）。

### 7. 删除人设自动解绑

`deletePersona` 先把引用它的 Bot 的 `persona_id` 置 0，再删表行。否则会留下悬空引用——`applyPersonaToPrompt` 查不到人设会退回原提示词，表面上「正常」，但用户以为自己还绑着什么。

### 8. 前端：人设页 + Bot 详情块

- 侧栏新增「人设」页签：卡片列出人设名、参与度、角色设定摘要、「使用中：某某 Bot」。最后一项是为了让用户在删除前看到影响面。
- Bot 详情新增「当前人设」块，位于 System Prompt **之上**：人设是「他是谁」，提示词是「怎么说话」，阅读顺序上人设在先。这也正是参考稿（图 4）指示的位置。

## 顺带修掉的 UI 缺陷

这几个都是截图后发现、与需求无直接关系但确实坏了的地方：

1. **窄窗口内容区塌成 0**：`#sidebar { width:260px; flex:none }` 在窗口变窄时不肯收缩，内容区被挤成 0 宽，输入框只剩 22px、发送按钮跑出视口。改为 `flex:0 1 260px; min-width:0` + 三档断点。
2. **Bot 页右侧整片空白**：有 Bot 但未选中时 `#bots-empty` 与 `#bot-detail` 同时隐藏。
3. **记忆页「刷新」被裁掉**：`grid-template-columns: 240px 1fr` 中 `1fr` 的最小内容宽度把右列挤出视口；`#view-memory` 此前完全没有容器样式，标题贴边。
4. **人设弹窗保存按钮看不见**：字段多，整框滚动把按钮推到可视区外。改为内容区滚动 + 底部按钮吸附。

## 不变量（不得回归）

- 参数化 SQL；`persona_id` 用 `std::to_string` 传参。
- `persona_id = 0` 时 `applyPersonaToPrompt` 必须**原样返回**输入（升级兼容）。
- 人设内容全空时退回原提示词，不得返回空串（否则系统提示丢失）。
- 迁移幂等：`ensureBotCol` 走 `PRAGMA table_info` 判断，重复启动无副作用。
- 内置人设不可删；删除自定义人设必须解绑引用。
- `/api/v1/*` 仍需 `X-Orua-Token`（`/health` 与 `*/avatar` 豁免）。
