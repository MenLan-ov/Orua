# v0.5.3 规格：插件页重做与插件/技能可配置

## 背景

v0.5.2 解决了「插件能加但不能管」的问题，但界面仍是一张平铺列表：技能和插件混在一起，没有分组、没有搜索、没有状态总览；一个插件加错了只能删掉重建，无法临时停用，也无法限定只对某个 Bot 生效；技能没有参数入口，用户想给 `http_get` 配一个固定 URL 只能每次在对话里说。

参考稿给出的形态是：标题 + 副标、右上主操作、搜索、`N / M 生效` 计数徽章、刷新；内容按类别分组并带条数；卡片头部是名称 + 版本 + 状态标签 + 右侧图标按钮，下面是能力 id 药丸和简介。这套结构比原来的列表信息密度更高，也把「每个对象有独立设置」这件事显式化了。

## 目标

1. 插件页按参考稿重做布局，技能与插件分组展示。
2. 每张卡片有齿轮入口，打开后能改该对象的生效参数。
3. 插件能限定生效 Bot（多选，空 = 全部）与临时停用。
4. 有「测试连接」按钮，能在保存前确认 Webhook 可达。
5. 顺带修掉两个会直接影响上述功能的缺陷（https 无法投递、技能参数被清空）。

## 非目标

- 不做插件的权限模型或沙箱；插件仍按用户填的 URL 直接投递。
- 不改技能的调用协议（仍是 OpenAI function calling）。
- 不引入前端框架，保持原生 JS。
- 不做插件市场/导入导出。

## 设计

### 数据模型

`cfg::Plugin` 新增两个字段：

| 字段 | 类型 | 默认 | 语义 |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | 停用后不投递，配置保留 |
| `bot_ids` | `vector<int64_t>` | 空 | 空 = 全部 Bot；非空 = 只对这些 Bot 投递 |

`bot_ids` 选空数组表示「全部」而不是「一个都不投」，是为了让 v0.5.2 的旧配置读出来语义不变——旧文件里没有这个键，读成空数组即「全部生效」，升级不需要迁移脚本。

### 分发过滤

`EventBus::emit` 在投递前依次判断：插件是否 `enabled`、事件的 `bot_id` 是否落在 `bot_ids` 内。为此 `chat.completed`、`chat.error`、`session.deleted` 三处事件载荷都要带上 `bot_id`。`session.deleted` 需要在 `deleteSession` **之前**查一次会话拿 `bot_id`，否则删完就查不到了。

### 技能参数

按 `(bot_id, skill_id)` 存一份 JSON 对象。执行技能时把这份参数作为默认值，模型显式传的同名键优先——这样「配了固定 URL」不会挡住模型在别的场合传别的 URL。

`db::setBotSkills` 有个隐患：它做全量覆盖时会把 `params` 重置成 `{}`。技能页每次勾选都会调它，于是「勾选 → 参数没了」。修法是保存前先 `SELECT skill_id, params` 读进 map，写回时保留。

### 测试连接

`POST /api/v1/plugins/test` 同步 POST 一条 `{"type":"plugin.test",...}`。超时设 2 秒，与正式投递一致——如果这里放宽，用户会得到「测试通过但发不出去」的错误信心。

### Webhook 投递改用 WinHTTP

原先用 `httplib::Client`。两个问题：

1. 本项目 httplib 编译时未启用 OpenSSL，**没有 `SSLClient`**，`https://` 地址根本无法投递。
2. `parseUrl` 只剥 `http://`，`https://example.com/x` 会把 host 解析成 `https:`、path 变成 `//example.com/x`。

改用 WinHTTP 后：https 走 `WINHTTP_FLAG_SECURE`，且自动复用系统代理，与 LLM 请求行为一致（用户开了代理时插件也能通）。顺带把「只有 200 算成功」放宽为 2xx。

### 界面

```
插件 Plugin   [+ 添加插件]  [搜索框]        N / M 生效  [刷新]
┌ 说明段落 ─────────────────────────────────┐
内置技能  6 个
  [Bot 选择器]
  ┌ 计算器  已启用  ☑启用  ⚙ ┐
  │ calculator               │
  │ 四则运算表达式求值…       │
  └──────────────────────────┘
自制插件  3 个
  ┌ 说明段落 ─────────────────┐
  ┌ 聊天完成通知  生效中  ↑ ⚙ ✕ ┐
  │ chat.completed              │
  │ https://… · 生效范围：全部 Bot │
  └─────────────────────────────┘
```

图标用内联 SVG 而非 `⚙`/`↑` 字符——WebView2 里这些字符会被渲染成模糊小圆点或方向异常的箭头，看不出含义。

### 加载失败不给出可提交状态

技能状态未从服务端确认时，勾选框与齿轮置灰；即使强行派发 `change` 也会被 `submitBotSkills` 拒绝。否则用户一勾就会拿空集合覆盖服务端已有技能。保存失败同样撤销信任，需点「刷新」恢复——这一点与 v0.5.2 的既有约定一致。
