### Task 1: 修复 `consumeSse` 漏拼 `API_BASE`

**Files:**
- Modify: `src/AiCompanion.App/wwwroot/js/app.js`（`consumeSse` 定义）

**Interfaces:**
- Consumes: 模块级 `API_BASE`（`window.__API_BASE__` 或 `http://127.0.0.1:8765`）
- Produces: `consumeSse(path, body, handlers)`——`path` 为相对路径

- [ ] **Step 1: 先复现** — 用真实 GUI 点击发送，确认请求打到 `https://app.local/...` 并报 `ERR_FILE_NOT_FOUND`。

- [ ] **Step 2: 修改实现**

```js
// 页面由 WebView2 以虚拟主机 https://app.local 提供，相对路径会打到虚拟主机目录
// （ERR_FILE_NOT_FOUND），必须拼上后端真实地址。App.api.req 一直是 API_BASE + path，
// 只有这里从 v0.1.0 起漏拼——所有既有测试都用相对路径 stub 或 curl 直打后端，从未在
// 真实 WebView2 里点过发送，所以一直没暴露。
async function consumeSse(path, body, handlers) {
  const ctrl = new AbortController();
  App.state.abortCtrl = ctrl;
  try {
    const res = await fetch(API_BASE + path, {
      method: 'POST',
      headers: authHeaders({ 'Content-Type': 'application/json' }),
      body: JSON.stringify(body),
      signal: ctrl.signal,
    });
    // ...
```


期望输出全部以 `API_BASE` 或 `${API_BASE}` 开头。

- [ ] **Step 2: 修复**

```bat
rem VS 安装路径可能含中文（如 D:\...\VS\本体）。vswhere 按 UTF-8 输出，而 cmd 默认

rem 切到 65001 让 for /f 拿到的路径与磁盘上的真实路径一致。

```
